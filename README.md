# dylan-lebreton.github.io

Dylan Lebreton's personal wiki: https://dylan-lebreton.github.io

The site is generated by [Quartz v4](https://quartz.jzhao.xyz/) from the markdown files in
`content/`. The build and deployment happen automatically in GitHub Actions on every push
to `main`. The workflow therefore comes down to three steps: edit markdown, commit, push.
The site is up to date roughly a minute and a half after the push.

Local preview (optional):

```bash
npm ci                    # first time only
npx quartz build --serve  # http://localhost:8080, hot reload
```

## How to write a page

A page is a `.md` file in `content/`, and a subfolder becomes a section in the explorer
(nesting is unlimited). Files are named in `kebab-case` (for example `basic-concepts.md`),
without accents or spaces. `content/index.md` is the home page and must not be deleted. An
`index.md` placed in a folder customises that section's page; without one, Quartz generates
a plain list.

### The front-matter (the header between `---`)

Every page starts with a small YAML block:

```yaml
---
title: Basic concepts
tags:
  - rust
draft: true
---
```

- `title`: the title shown at the top of the page, in the explorer, in search and in
  links. **It replaces the `# Title`** you would normally write, since Quartz already
  displays it as an H1. The body of the page therefore starts straight at `##`, with no
  `#`. Without a `title`, Quartz falls back to the file name.
- `tags`: optional. Each tag gets an auto-generated page listing its notes.
- `draft: true`: optional. The page is built locally but not published.
- `rank`: optional. A number that forces the page's position (see below).

### Ordering pages

By default, the pages in a section are sorted alphabetically by their `title`, both in the
left-hand explorer and in a section page's list. To impose a different order, add a `rank`
key to the front-matter:

```yaml
---
title: Variables
rank: 1
---
```

The smallest number comes first. A page without a `rank` is sorted alphabetically, after
the pages that have one. To order a folder, put the `rank` in the front-matter of its
`index.md`. In local preview, a `rank` change is only reflected in the left-hand explorer
after restarting `npx quartz build --serve` (the section page list, on the other hand,
follows hot reload).

### Headings

`##` for sections, `###` and `####` for subsections. The table of contents on the right of
each page is built automatically from these headings.

### Links between pages

- `[[cargo]]`: a link to the page; the file name is enough if it is unique.
- `[[cargo|label]]`: a link with different text.
- `[[knowledge/rust/cargo]]`: the full path when the name is ambiguous.
- `[[knowledge/rust/|Rust]]`: a link to a folder (with the trailing `/`).
- `[[cargo#Dependencies]]`: a link to a specific section.
- A link to a non-existent page does not break the build; it stays dead until the page is
  created.
- External link: plain markdown `[text](https://…)`.

### Transclusion (embedding one page inside another)

- `![[cargo]]`: inserts the entire content of the page.
- `![[cargo#Dependencies]]`: inserts only that section.

### Images and files

The file is dropped into `content/` (for example next to the page), then called with
`![[schema.png]]`.

### Formatting

- Code: ` ```rust ` / ` ```python ` / ` ```bash ` blocks with automatic highlighting, and
  `inline` with backticks.
- KaTeX maths: `$e^{i\pi}$` inline, `$$ … $$` as a block.
- Callouts: `> [!note]`, `> [!tip]`, `> [!warning]`, `> [!example]`, foldable with the
  `> [!note]-` variant.
- Tables, lists, quotes, bold and italic: standard markdown (GFM).
